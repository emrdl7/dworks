## 0. 사용자 mandate

> "사이드패널에 너무 많은게 쌓이는거 아니야? 해당 아이템 선택후 마우스오른쪽버튼 누르면 제어가 된다거나... 트리에서 마우스오른쪽버튼이나 드래그로 제어가 된다거나... 다양한 아이디어로 반영해봐... 상호 협의하에..."

→ 인터랙션 분산. 인스펙터 외 _캔버스 / 레이어 / 컨텍스트 메뉴_로 자주 쓰는 작업 옮김.

본 토픽은 _전체 영역 합의_ + 단계 분할 + 1차 우선순위 결정.

## 1. 인터랙션 영역 후보

### 1.1 우클릭 컨텍스트 메뉴

- **캔버스 노드 우클릭** → 메뉴 (이동/복제/삭제/숨김/잠금/위로 가져오기/뒤로 보내기)
- **레이어 우클릭** → 동일 메뉴 + name 변경

권장 1차 — 작은 코드 + 큰 효과.

### 1.2 드래그 인터랙션

- **레이어 패널 드래그** → 노드 순서/parent 변경 (m2-structure-ops 외 cross-parent 가능)
- **캔버스 노드 드래그** → 위치 직접 조정 (구조 이동 외에 _자유 위치_? 본 mandate 외)

레이어 드래그가 _구조 편집 자연_. 캔버스 드래그는 _절대 위치_ 영역 (현재 flex layout — 절대 위치는 별도 토픽).

### 1.3 캔버스 인라인 컨트롤

- 선택 노드 위 떠 있는 _작은 toolbar_ — 자주 쓰는 작업 (Figma/Sketch 패턴)
  - 텍스트: bold/italic 즉시
  - 이미지: 크기/맞춤
  - 모든 노드: 복제/삭제

권장 후속 — UI 복잡도 ↑.

### 1.4 인스펙터 자동 접기

- 자주 쓰는 섹션만 펼침
- 노드 type 별로 _기본 펼침_ 다르게 (text → 타이포 / image → 이미지 구도 등)

권장 후속 — 작은 UX 디테일.

## 2. 1차 우선순위 (Claude 권장)

**1순위: m2-context-menu** — 우클릭 메뉴 (캔버스 + 레이어).
- 가장 큰 _인스펙터 부담 감소_ + 디자이너 일상 핵심.
- 코드 영역: page.tsx 내 ContextMenu 컴포넌트 + 이벤트 핸들링.

**2순위: m2-layer-drag** — 레이어 드래그 정렬.
- 구조 편집 ops를 _드래그_로 단축.
- 같은 parent 내 순서 변경 + cross-parent (후속).

**3순위: m2-canvas-toolbar** — 캔버스 인라인 toolbar.
- 큰 UI 변경, 더 많은 합의 필요.
- 후속.

**4순위: m2-inspector-smart-collapse** — 인스펙터 자동 접기.
- 작은 UX, 후속.
